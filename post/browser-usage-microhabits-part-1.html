我觉得，可以把浏览器搜索放上去。这些技巧自己也可以学习一下，然后做一个总结，补充内容。这两份就当做是对浏览器信息的搜索技巧。

开始

在日常生活中，我们常常会遇到下面这样的场景：

  • 碰到一个棘手的问题，很难找到对应的资料，一时烦恼不已；
  • 一些未来生活中可能会碰到的问题，平常看文章时没有留意，用时又找不到；
  • 每当发现新的、有价值的网站，收藏后，就没有下文了；

这些问题并不是特别突出，也不是十分有必要。不过，用一些微习惯来优化它，把这些变成信息养料，我想在工作、学习中都能有更多的收获。

通过一些小小的改变，我想处理好自己的信息流，让自己能够更好地找到想要的资料。把笔记和资料真正地用起来。

如果你也对这方面有兴趣，不妨继续看下去，我相信这个信息流整理的思路还是不错的。

信息流

关于，信息流我这里指的是个人对信息的把控，而不是组织、企业的。信息流也有指商品流通中的企业管理，也有人把知识管理比喻成个人的信息流，这些讲法我都赞成。

我这里用的是信息流的广义上的定义：

信息流的广义定义是指人们采用各种方式来实现信息交流，从面对面的直接交谈直到采用各种现代化的传递媒介，包括信息的收集、传递、处理、储存、检索、分析等渠道和过程。

像下面这样的，就是信息流在企业中的使用。这里我们可以简单了解一下信息流的功能，这样也好理解后面想法和意图。

评价企业成功与否，一个简易的办法是看其物流、工作流和信息流“三流”的情况，其中，信息流的质量、速度和覆盖范围，尤其可以“映照”企业的生产、管理和决策等各方面的“成色”。因为物流、工作流在企业的“生命活动”中无不最终以信息流的“高级形式”展现，就象生物体的所有活动都是基于神经系统传递的生物电信号一样。因此，深入认识“信息流”，将掀开企业发展的新视角。

关于信息流的百科介绍大家可以去查看，这里我就把百科里面信息流的一些功能和这些习惯的使用联系起来，方便大家理解。

其实，这里的流程更加倾向于 GTD 的管理理念，有兴趣的小伙伴可以去看看。

信息流使用

这么好的知识肯定要拿来使用的。我们分成三个部分来把它拆解，并讨论它是怎么应用到习惯里面去的。

1. 信息流的功能

联接功能：流通整个体系需要不同要素和其集合，那么它们就是通过信息联接在一起的。信息把资料给联接起来，去做一件事情，一个项目。

调控功能：让信息联接后，我们对信息就有一定的接收、加工和利用。这样，我们就可以调控自己的行为。也就是通过信息的变化来影响当事人的行为。

决策功能：当资料、要素在不断变化过程中，信息也就会不断变化。因此，决策当事人越理解信息的动态变化，所做的决策也就更恰当。信息越完善、充分、及时，不确定性就越少，决策就可以越合理。

2. 信息流与事件的关系

信息流，从我的理解上，是为事件准备；也就是这个信息我是需要的，能够从中获得自己想要的价值。也因此，我才支持对信息的筛选和整理。

不过，信息流不是事件，不能代表事件去处理。但是，事件的动态变化可以通过信息流来反映出来，这让事件的处理变得更加有条理。

3. 信息流的执行过程

信息收集：信息收集是信息流运行的起点，它是分散的信息向收集者集中的过程。信息的收集者成为信息的信宿，他是按照自己的目的和需要来集中有关信息。

收集信息的质量,即信息的真实性、可靠性、准确性、及时性，决定着能否达到预定的目的和能否满足需要。因此，收集信息必须遵循一定的原则进行。

  1. 具有明确的目的性。收集信息的目的决定着收集的范围、深度、方法和费用。目的不明确将会导致无边际的收集，降低收集质量，造成不必要的浪费。
  2. 收集目的是按照企业经营的需要而确定的，如果是战略性的目的，所涉及的范围就比较大。如果是某一方面很具体的目的,所涉及的范围就要小得多。
  3. 确定深度和精度。这是按照收集目的的要求来确定的。不同的目的对深度和精度的要求也不相同。深度和精度决定着收集的难易程度和费用大小，是收集者必须考虑的问题。
  4. 选择信息源，建立信息渠道。信息源的选择取决于收集目的及信息内容。一般来讲，选择信息源先要利用现有信息和现有信息渠道，当现有信息不够用时，就要寻找新的信息源。
  5. 由于流通活动是连续进行的，其中有些内容是不断重复的。因此，确定具有连续性相对稳定的信息源和信息渠道，是非常有意义的。

信息处理：收集来的信息往往是零乱的，有时甚至是片面的、虚假的，必须经过处理才能去伪存真，归纳出结果，提高信息的使用价值。信息处理主要包括以下内容：

  1. 分类及汇总。对零乱的信息按照一定的标准进行分类整理，重新组合后，才能显示出信息之间的相互联系，为分析、比较、判断创造条件。
  2. 分析、判断、形成结果。大量的信息罗列在一起，有真有假、有主有次、相互孤立、形式各异，既不容易存储和检索，也难以观察到信息所反映的事物本质内容。
  3. 信息处理是对信息进行再创造的过程，是信息流运行非常重要的环节。
  4. 存储和更新。经过处理的信息，有时不是立刻投入使用，有的虽然己经使用过，但仍然有再利用的价值,这就需要进行信息存储。

信息传递：信息传递是信息从信息源发出，通过一定的媒介和信息渠道传输给接收者的过程。

信息传递到接收者之后，接收者就成为信息的使用者，对信息加以利用，实现信息的使用价值。信息的使用价值是信息的知识性、效用性对人类特定需要的满足。

上面这些大多是百科内容，不过相信大家也已经明白信息流是怎么一回事了。在个人的笔记里面，最主要应用的就是把信息给收集，整理，加工变成自己的信息养料。最后，把这些信息养料去做想做的事。

文章所指的信息可以是很多种，这里以常见的文章和链接为例子。

需求

项目

我的这个信息整理的思路来自于我的一些麻烦。比如，我平常的时候会浏览一些网站，有的时候看到好的网站没有保留下来，或者收藏了自己也没有去处理。

渐渐地，我就不知道当时为什么想收藏这个网页，是因为工具，还是资讯内容？我不知道。所以，我想做一个收藏，把这些都放上去。

特别是，有一些网站只是用了一次，说没有印象又有一些印象，但印象又不是特别深。加上，在使用网站的过程中有一些心得、Tips 之类的，我想保留下来，又找不到合适的笔记方案。

所以，我就想通过 Notion 的 Webclipper 来实现这个功能，把网页收藏起来。当我把网页收藏并打算整理的时候，我发现可以用一个事件来把这些都放起来，不管是网址还是笔记。

这样，当我遇到相类似的情况，我就可以打开这个页面，能够一下子就知道用那些工具或者那些网站。我把这个称为 「项目」。

项目思维是我特别喜欢的一个思维，在许多问题中我都会用到它。日后可以写一篇文章来专门介绍项目思维是什么样的，以及它是怎么运用的。

情景

开始设问的场景都有一个特性，那就是它们的信息价值是暂时的。换言之，这个事件我并不知道什么时候会处理，或者它不是当下要处理的事情，但是在未来的时候可能会用到，想要去做这样的一个准备。

这样的需求是对某个不是当下事件的信息整理。这种需求并不是很罕见，比如，对于大学里需要考研的学生来说，把目前所知道考研的信息汇总起来，这样等到来时下定决心时就可以去做。

也不影响当下正在做的事情，能够提前规划。又比如，对于准备要找工作的人来说，可能在前期会接触到各式各样的求职信息。

当前并不一定都能用的上，把找到信息全部扔掉又比较可惜。不如做一个备份，以备后面想要换工作时的考虑。

又比如我个人，是学英语专业的。这个学期开了笔译课，想要去做一些翻译的研究。但是，我可能不会一直划一个大块时间来找资料。我可能会找到当下需要的资料，赶紧去看。不是急需的，我想备份下来等到暑假有时候再去看。

基于上面的场景，我想做一个信息的协同工具。让这些信息不只是有整理，不只是有归类，还可以更好地利用信息推动我想做的事情。

浏览器

另外一个来源，是浏览器网址导航。当我收集了一段时间的网址，准备把它们整理、归类放到网址导航上时，我发觉这个有很大的不方便。

比如，有一些网址是工具性质的，有一些是信息性质的。还有一些网址是同其他网址相联动的，两者之间联系可以处理一个问题的。

那时我在想，为什么不构建一个新的网址导航，让上面不只有归类和标签，还有更多信息联动。让两个不同类别的网址联系起来，搞出更大的「信息空间」。

曾经网上流传一种笔记的分类方式，是根据图书的分类原则归纳自己的笔记。当然，也有人在这个基础上构建一套完美的笔记归纳体系。

当这样的方式也很好，可是我在尝试一段时间后就放弃了。一个是这样做，在我看来比较繁琐，不是特别习惯。另外一个是，我觉得自己并不需要和图书一样，而是把笔记同自己的生活联系起来。

比如，我正在读的一本书，那么我就想这本书的笔记离我近一些。如果我做了某个读书的专题，那么我就做一个 「已完成」 的标识，这样直接通过搜索把这个内容从笔记中调出来。

随着做的笔记越来越多，我更加发觉这些笔记和我，这个主体间的关联重要性。而且，我也不需要把笔记分享给别人看。一般我分享的都是写好了的文章，而不是生硬的笔记。

怎样处理笔记和资料与主体间的关联，是我区别于以前做笔记的思路。这个时候，又可以把 L 先生的名言放出来了：「以我为主，为我所用」。

就这样，我有了一个大胆的想法，用 Notion 来整理网址链接间的信息交汇。然后，通过 Notion 来做出一个更大的空间。

基于上面三个想法，我就有了一个思路，那就是把信息通过项目事件来推动。下面就来看看我是怎么做的吧。

Notion

一直以来我都觉得 Notion 作为一个笔记最大的优势在于「协同性」，这个功能可以做到一些其他笔记软件做不到的功能，甚至是用户也想不到的功能。

比如，我想看到这些文章它们之间的对比状况。如果是之前，可能是在一张笔记里面用一个表格来做到，加上链接跳转。可在 Notice 里面，用 Database 就可以做到。把 Database 嵌入到 Page 里面，就可以看到这个对比，然后做笔记。

相较于其他笔记，Notion 做到的是信息展示多样性，All-in-one 的思路让这个展示变得更加可能。我做一个小小的猜想，在未来，笔记软件会更多的同资料联系起来，让它们完成同一个事件，带来更多的视角。

资料是还没有拆开的信息包，笔记是已经加工好的信息包。两者相互交融，让生活更加条理，更加清楚。再配上本地化，一切都有可能。

方法

更多的就不说了，回到主题来。做法其实很简单，去浏览器拓展里面找一个 Notion Webclipper 插件，然后在 Notice 里面单独做一个 Website 的 Database。

这样，一旦发现好的网站，那就收入到这个 Database 里面上。然后，有时间就去查看，把它们放到一个好的位置。

当然，这里面可以添加更多的属性、标签之类的。完全可以根据自己的需求来定义，找到自己的出路。

正如前文所说的，做这个不是为了囤积信息，而是优化查找信息间的流程。

案例

这里我想以学习英语和考四级为做一个例子来解释这个流程是怎么处理的。

当我们学习英语时，需要查询单词。我们可能会找到一系列字典网站，然后把它们都放到 Database 里面。在使用了一段时间后，会发现有一些网站加载比较慢，有一些比较全面。

这个时候就可以新建一个 Page 命名为 “查单词” 把这些内容记下来，然后决定自己常用那个网站是什么。这里的 Page 同样可以用 Database 来处理，这样方便后面整理信息，切换视角。

假如，现在需要考四级了，想要一个轻便查单词的，能够快速查多个单词的，不需要那么全面的网站。去这个 Page 里面一看，发现没有这样的网站。

那么，这个时候就可以去互联网上搜索有没有这样的网站。又或是这个需求，其他人是用怎样的方式解决的，看有没有适合自己的方法。

当你找到了一个可以查多个单词的网站或者一个思路后，你就可以把这个网站放到 Website 的 Database 里面去。然后，在查单词页面把这个思路给补上去。

过了一段时间，需要考研了，又或者需要考证了之类的，这个时候又需要这个工具了。但是，发现如果这个时候再去互联网上搜索，可能就很难找到了。

这个时候，就可以去查单词的页面上找到这个网站，甚至还可以找到当时的一些心得、Tips。这不是很节省时间吗？做笔记的目的就是要区别没有接触过的。

虽然，很多人做完笔记后还是会忘记，但是这不影响自己已经加工过的事实。只要再次接触，给予相应的材料，我相信还是能找到当时的情况。

延伸

上面就是一个很简单的使用，但已经表现出用法。不只是在时间上的，还可以是行动上的。比如，当我做翻译的研究时，可以放大来，搭建好杠架；也可以缩小来，专注某个板块。

甚至，我还可以跳出翻译的视角，把它同语言研究和语言现象联系起来，这样可操作的空间就更大了。而这，仍然是以一个事件，一个项目为中心为变动的。

你依然可以找到这种变动的思路，就像 Notion 一样，把知识当做积木，搭建你想要的任何领域。我想做的，就是一个简单的工具随着我的思维做更多更复杂的事情。

而且，这样的变动也不是很复杂的，也不是单一的。像画家手上的画笔一样，几种简单的颜料画出各式各样的作品。思维也是如此。

结尾

本来打算把后面两个内容「多维表格」和「书签」也写完的，但是这次内容加入了信息流的讲解，就字数达到了 5000 多字，所以我打算把它分成两个前后篇来写。

整个信息流体系是很不错的，把后面的内容补充完整，就可以使用这个信息流来做事情了。细心的小伙伴已经发现了，这个是把做研究前的查找资料过程放到日常生活中来整理来的。

喜欢这篇文章的小伙伴可以期待一下后面的内容是什么，它的框架我已经放到文章的前面。这个思路我用得还不错，不知道其他小伙伴尝试用得怎么样，希望能够给我一点点反馈。
